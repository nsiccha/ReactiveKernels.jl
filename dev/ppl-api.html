ReactiveKernelsPPL.ArrayParameter Type
julia
ArrayParameter(name, family, args, dims, support_override, label)

One declared array-valued parameter: a plain value the model reads by name (z, z[g], z[1], B * w, L[2, 1]), never a hidden coefficient block. Two kinds of family:

  • An elementwise family (any SAMPLED_ARITY key): the surface z[1:K] .~ Normal.(mu, s) — independent draws per element, with Distributions.jl Normal.(…) broadcast semantics. args use positional keys (arg1, …); each is a Real literal, a Symbol (a scalar parameter/assignment name, an array parameter, a data column, a derived column, or a vector-valued assignment — read per element), a literal vector (Expr(:vect, …), per element), or a value expression (per element). support_override follows SampledParameter (HalfNormal.(s) is :normal + :positive).

  • :lkj_cholesky — L ~ LKJCholesky(K, eta): the lower-triangular Cholesky factor of a K×K correlation matrix (Distributions.jl LKJCholesky(K, eta) density, uplo = 'L'). args = (arg1 = eta,), a finite positive literal; dims is [K, K].

  • A multivariate slice family <stem>_<slices> (mv_slices.jl): eachrow(B[a, b]) .~ D (_rows), eachcol(B[a, b]) .~ D (_cols) or b[ax] ~ D (_vector) — every slice of the array one draw of the multivariate D. Stems: mvnormal_cholesky (args = (arg1 = mean, arg2 = factor)), mvnormal ((arg1 = mean, arg2 = covariance)), dirichlet ((arg1 = concentration,), rows/cols only) and ordered_normal ((arg1 = m, arg2 = s, arg3 = K) for Ordered(Normal(m, s), K), rows/cols only). A vector argument is a shared value or a per-slice :(eachrow(M)) / :(eachcol(M)) expression; matrices and scalars are shared. Multivariate normal slices are centered (the entries are the coordinates); simplex and ordered slices constrain along each slice.

A phi ~ Dirichlet(alpha) simplex is not an array parameter: it stays a VectorParameter, which definitions already read as a model-level value (phi[1], cumsum(phi), a gather cum[c]).

dims holds one entry per array axis, each either a literal Int (from 1:K) or the surface sizing expression, resolved against bound data: :(levels(g)) (the sorted distinct values of grouping column g; reading z[g] then looks each observation's value up on that axis), :(length(levels(g)) - k) (from 1:length(levels(g)) - k: a positional axis of that many elements, k a literal ≥ 0, bare length(levels(g)) for 0), :(axes(M, d)) or :(size(M, d)) (axis d of a bound matrix or a design matrix M). Arrays have one or two axes.

ReactiveKernelsPPL.LikelihoodSpec Type
julia
LikelihoodSpec(family, link, response, predictor, scale, weights, evidence, label[, trials[, range]])

One independent response. scale is the response's auxiliary — Gaussian sigma, NB2 dispersion phi, Gamma shape alpha, hurdle p_zero, InverseGaussian shape lambda, BetaBinomial2 precision phi, VonMises concentration kappa, NB1 success probability p, LogNormal scale sigma, Weibull shape k — either scalar (parameter, assignment, folded literal, or a raw per-observation data column) or a ScalePredictorRef. The latter includes LogNormal sigma and Weibull k. Probability auxiliaries (hurdle p_zero and NB1 p) take values in [0, 1]; other scale/shape auxiliaries take positive values. The link need not guarantee support: the density checks the evaluated value. (One slot covers every admitted family; a two-auxiliary family such as Beta needs a new field — noted, not built.) nu is the StudentT degrees of freedom, nothing otherwise: a sampled parameter/assignment name, a bound data name, a finite-positive literal, or a ScalePredictorRef (predictor-fed per-observation nu — the scale-slot mechanism, with its own _ppl_sc_<label>_nu node so scale and nu predictors coexist). zi is the ZIP/ZIB zero-inflation probability and accepts the same value forms. Fixed nu data must be finite positive reals; fixed zi data must be finite reals in [0, 1]. A value is fixed when it reads no sampled name, as a column, a computed argument or a definition, and binding checks the rows the response observes. Model-valued inputs use the lazy density guard. weights is a frequency/power-objective column (D1); analytic/precision weights fail closed emitter-side. trials is the Binomial/BetaBinomial2 trial count (Int column or Int literal), nothing otherwise. range carries a literal y[1:N] range, or the indexed response expression for eachindex, axes and : selections, including positive literal trailing indices. nothing means the whole column. Literal one-dimensional ranges retain their full-cover check; indexed expressions select the stated response cells. An explicit indexed observation loop also selects its row operands before evaluating the retained cell; a top-level slice uses ordinary broadcasting.

Leveled families (categorical / ordinal / multinomial) use the trailing fields, built with keywords (n_levels=, thresholds=, extra_predictors=, count_columns=, ordinal_structure=, discrimination=, threshold_columns=); every other family leaves them at their defaults:

  • n_levels: category count K (nothing = infer at bind: from the response column for OrderedLogistic/Ordinal/Categorical, structurally — 1 + predictor count — for CategoricalLogit, structurally — column count — for Multinomial).

  • thresholds: shared ordered/vector parameter (VectorParameter), shared data vector, or ThresholdRows for vectors broadcast per observation for OrderedLogistic/Ordinal; nothing otherwise.

  • extra_predictors: CategoricalLogit non-reference predictors after predictor (class order 2..K is [predictor; extra_predictors...], K−1 total); empty otherwise.

  • count_columns: Multinomial count columns after response (category order 1..K is [response; count_columns...]); empty otherwise.

  • ordinal_structure: :cumulative/:stopping for OrdinalFam, nothing otherwise.

  • discrimination: OrdinalFam positive latent scale (nothing = 1.0), nothing otherwise: a positive Real literal, a finite-positive data column, a legacy predictor name, or a ScalePredictorRef whose link belongs to this discrimination use. Modeled values have finite-positive support checked by a lazy likelihood guard.

  • threshold_columns: OrdinalFam per-threshold design columns (StoppingRatio only), empty otherwise.

  • threshold_coefs: the (K−1)×p threshold-coefficient matrix packed as a :vector_normal VectorParameter (required exactly when threshold_columns is non-empty), nothing otherwise. Stage-major: stage j occupies entries (j−1)*p+1 .. j*p.

  • threshold_effects: an ordinary N×(K−1) matrix value for stopping-ratio responses, subtracted from thresholds[j] - eta[i] before discrimination. It replaces, and cannot accompany, the legacy threshold design fields.

Multinomial/Categorical responses name their shared-simplex VectorParameter in predictor (no linear predictor — the scan-state precedent). A Gaussian-identity response may likewise name a PlateParameter in predictor: a latent-mean observation (x_obs ~ Normal(x_true, sd) with scalar constant sd — the SB me mirror).

Joint correlated-outcomes responses (MvNormalCholeskyFam, SB [y1..yK] ~ MvNormalCholesky([mu1..muK], L)) use the trailing joint fields, built with keywords (extra_responses=, factor_scales=, factor_corr=); every other family leaves them at their defaults:

  • extra_responses: joint outcome columns after response (outcome order 1..K is [response; extra_responses...], K ≥ 1); empty otherwise. Each outcome's mean is an identity-link linear predictor: predictor for outcome 1, extra_predictors (reused from the CategoricalLogit shape) for outcomes 2..K.

  • factor_scales: the joint factor's positive scale vector (VectorParameter, K scales), nothing otherwise.

  • factor_corr: the joint factor's LKJ Cholesky factor (VectorParameter, K×K), nothing otherwise.

Joint widths are structural (K = 1 + length(extra_responses)): no n_levels, no bind-time size inference — the factor parameters carry concrete sizes validated against K.

GLM-object responses (NormalIDGLMFam, BernoulliLogitGLMFam, PoissonLogGLMFam) name their design matrix in predictor (no linear predictor — the object owns eta, the Multinomial/Categorical scan-state precedent): an intercept-free DesignMatrix, or any matrix value (bound data, a definition) the object reads whole. They carry the split coefficients in the trailing glm_alpha/glm_beta fields, built with keywords; every other family leaves them at their defaults:

  • glm_alpha: the scalar intercept — a value's name or a number (the generator prepends the ones column and alpha; a literal zero prepends nothing) — nothing otherwise.

  • glm_beta: the coefficient vector's name (one element per matrix column), nothing otherwise. A declared array or any other value carries its own prior; otherwise the plan's population priors address each design-matrix column by the response label (_glm_coefficient_block).

Finite-mixture responses (MixtureFam, SB y ~ MixtureModel(comps, w) mirror) carry K same-family univariate components in the trailing mixture fields, built with keywords; every other family leaves them at their defaults:

  • mixture_family: the shared component family (v1: Gaussian/identity, Bernoulli-logit, Poisson-log, Binomial-logit, NB2-log, Gamma-log, Beta-logit), nothing otherwise.

  • mixture_locs: per-component location uses, length K (K ≥ 1): each a predictor name (link-space, inverted per the component link), a sampled scalar parameter name, or a numeric literal (both constrained-scale, no inversion). Empty otherwise.

  • mixture_scales: per-component scale uses, length K: each the component's scale-slot use (nothing, parameter/assignment name, literal, per-observation column, or ScalePredictorRef) — required exactly when the component family takes a scale auxiliary. Empty otherwise.

  • mixture_weights: the length-K mixing weights: a literal Vector{Float64} (finite, nonnegative, sums to 1), a shared bound numeric vector, a :simplex_dirichlet VectorParameter name, or a MixtureComplementWeights pair (K == 2), or MixtureWeightRows naming an ordinary value with one probability vector per observation; nothing otherwise.

  • mixture_trials: one trial-count column or literal per Binomial component when their arguments differ. Empty when trials supplies the shared argument.

  • mixture_components: lowered constructor graphs for heterogeneous full-real components. Each carries its own argument list; the legacy family/location/ scale slots remain empty on this route.

predictor is an anchor only (first location predictor, else first scale predictor, else the weights simplex name, else the first location/scale parameter name, else the response name); scale is nothing. Mixture widths are structural (the number of component graphs or location slots): no n_levels, no bind-time size inference. Binomial components may have distinct trial counts. Case-A mi() missingness (SB parity, log density only) names its observed-row index column in the trailing mi_jobs field, built with keywords (mi_jobs=); every other response leaves it at nothing:

  • mi_jobs: the Jobs column (sorted-ascending unique Int row indices, a nonempty selection on the response's full observation axis). The response, every Multinomial count column and every joint outcome cross PACKED (aligned with Jobs); they ride the managed-columns exemption. Vector predictors and trials gather by full-row Jobs; shared probabilities and covariance factors stay whole. GLM objects select full design rows before constructing eta. Only observed rows contribute, with no missing response latent (SB keeps y_mis in generated quantities here). Scalar observation families compose with weights, evidence, ranges and trials. A range filters Jobs on the full axis and the same packed outcome positions; Case-B downstream merged-response uses fail closed emitter-side.

VonMises responses (VonMisesFam, SB brm_von_mises mirror) carry the principal-interval endpoints in the trailing interval field, built with keywords (interval=); every other family leaves it at nothing:

  • interval: nothing for exact VonMises (moving inclusive support [mu - pi, mu + pi]), or the (lo, hi) literal pair for CircularVonMises (fixed half-open support [lo, hi), finite with lo < hi and width exactly 2pi — the BRM _brm_circular_interval rule). The generator wraps mu into [lo, hi) per cell and guards y to the support, exactly the SB branch structure.

ReactiveKernelsPPL.ParameterGeometry Type
julia
ParameterGeometry(shape, unconstrained; support, constrain, unconstrain,
                  logjac, coordinate_names=nothing)

Caller-owned parameter geometry. shape is the constrained shape (empty for a scalar); unconstrained is the packed dimension, independently of that shape. They may contain data-only Julia expressions, evaluated when binding data, never by evaluating sampled values. support describes the support; the density and inverse must enforce it. Endpoints are ordinary pure Julia callables: constrain(u, shape, args...), unconstrain(value, shape, args...) and logjac(u, shape, args...). The first returns the constrained value, the second a packed vector, and the third the log absolute Jacobian. Host and kernel execution call these same endpoints. coordinate_names, when supplied, has one Symbol per packed coordinate. Draw generation is outside this contract.

Endpoints may also be function-shaped @kernel graphs. The descriptor prepares their host callables once; generated transforms compose the graph when every argument is explicitly supplied (including keywords). Thus supported row operations retain their locality and actual coordinate dependencies. Calls with omitted defaults or splatted arguments retain the prepared numerical path, as do ordinary Julia callbacks. A local transform does not factorize its density.

ReactiveKernelsPPL.initialize_filter_smc Function
julia
initialize_filter_smc(target; rng::Xoshiro, members=64, particles=128,
                      window_length=32, ess_fraction=0.5,
                      options=SMCOptions(), history_limit=32,
                      boundary=nothing, max_reflections=16)

Initialize an owned parameter ensemble from its carried Gaussian and a separate conditional particle filter per member. Each new record reweights members by their predictive scores. Replenishment is triggered by the effective sample size over distinct parameter positions: the weights of bitwise-identical members are summed, so resampled copies count once. When it falls below ess_fraction*members, or any member has zero likelihood, resample the current parameter/conditional-filter pairs by their updated weights and move the selected members. Their retained window likelihood estimates and conditional clouds survive selection. Only one fixed-budget replenishment is attempted per step.

Each move proposes a Gaussian random walk whose covariance is 2.38^2/d times the members' weighted covariance before resampling (Roberts, Gelman and Gilks' scaling), fixed for the whole replenishment. That covariance keeps up to max_reflections leading correlation directions of the members, fitted in their marginally standardized frame with WarmupHMC.fit_gaussian_moments, so coordinates on very different scales are treated alike. The retained directions keep their weighted variance, and the remaining directions share the remaining standardized variance equally (probabilistic PCA). At most the distinct-position ESS minus 2 directions are kept. With none, or max_reflections=0, the walk is diagonal with the members' weighted marginal spread. Work and storage are O(members × d × directions), and no d × d matrix is formed. A diagonal walk leaves the narrow parameter combinations that the data pin down, such as a hierarchical intercept plus its group effects, and is rejected there. Its particle-Metropolis acceptance ratio is the window Gaussian prior ratio times the proposed/current window likelihood estimate ratio. Each proposal rebuilds conditional states from the frozen boundary. Rejections retain the previous estimate and conditional cloud. The kernel contributes only moves, the proposals per member. A coordinate whose weighted spread is zero cannot move: a population whose spread has vanished stays collapsed and fails as described below. Its recovery needs the independently tuned kernel of rejuvenate_smc.

After window_length records, replace the parameter posterior by a Gaussian with the members' weighted mean and their weighted covariance, summarized as above (up to max_reflections leading correlation directions). Then independently resample the weighted finite states into a pool of particles states as the next boundary, and draw a new ensemble and independent initial state clouds from these summaries. A diagonal boundary (max_reflections=0) treats the marginal widths of correlated parameters as independent information. Where the data inform only combinations, such as a hierarchical intercept and its group effects, the next window then contracts the population again, and every window compounds it. The calibration you supply is the first window's prior, so carry it with the same correlated summary (carry_smc(fit; parameters, basis=:correlation)); a diagonal calibration over-contracts the first window, and basis=:fit keeps few correlations when parameters differ greatly in scale. This discards parameter–state dependence and Gaussianizes the parameter posterior; it is an explicit assumed-density approximation, not exact full-history SMC². With a finite ensemble, the spread in directions that the data never inform still drifts downward from window to window, because each boundary estimates it again from the members; more members reduce the drift. Nonpositive/nonfinite marginal scales fail with SMCDegeneracyError at rollover; no scale is invented. Full spatial coincidence is checked on input and after the configured mutation pass, so resampling from one parent still gets its chance to move. An error preserves the input state in error.state and the rejected summary in error.diagnostics; no observation or RNG draw is committed on failure. Attempt explicit rejuvenate_smc recovery before retrying that observation. A constant coordinate alone is allowed within a window, until a Gaussian boundary needs its positive marginal scale. Cost and retained state are bounded by members, particles, groups and the chosen window length, not elapsed time.

Use filter_step/filter_stream, filter_checkpoint and resume_filter(target, checkpoint). Records include observations, inputs and optional active groups; missing observations keep the ordinary filter meaning. This learning route consumes new data once. For state-only training warm-up, first use the ordinary filter, then pass its state as boundary. Its weighted finite states are pooled independently of the new parameter draws; its time and group clocks are preserved, but its training scores are not added again. The boundary filter must have the same source/configuration identity. The learning state retains the sampled pool, never that old filter or its history. Caller RNGs, input states and observations remain unchanged on success/failure.

Supported read-only diagnostics on the returned state are positions (unconstrained static coordinates, one member per column), parameter_mass (normalized weights), time, window, window_length, records (the retained window; use length(state.records)), predictive_logscore, log_normalizer and history. Each retained history entry exposes time, window, window_steps, parameter_ess_before, parameter_ess_after, distinct_ess_before, distinct_ess_after, replenished, boundary_reset, boundary_directions, unique_parents, proposals, accepted, distinct_members, moved_members, coordinate_sd, kernel, proposal_scale, proposal_directions, kind, likelihood_evaluations, reference_evaluations and predictive_logscore. kind is :assimilate or :rejuvenate. parameter_ess_* counts members, copies included; distinct_ess_* counts distinct parameter positions and triggers replenishment. proposal_scale is the random walk's per-coordinate standard deviation in an assimilation replenishment (empty otherwise), and proposal_directions the correlation directions it kept. boundary_directions is the number the step's rollover kept (0 without one). reference_evaluations counts NUTS steps on the Gaussian reference, which only :rejuvenate recovery takes. moved_members counts final positions differing from the selected parent (or recovery input); accepted proposals may leave a position unchanged. coordinate_sd is the weighted marginal spread in unconstrained coordinates. History is capped by history_limit; counting replenished there counts only retained steps. For lifetime counts, accumulate the latest entry after each step with history_limit >= 1. Equal weights after resampling do not demonstrate mixing; inspect pre-resampling ESS, ancestry, actual movement and spread too.

  • the opt-in plate reverse (ReactiveKernels.with_plate_reverse), which differentiates the ordinary program;

The lifecycle keywords apply to pilot=:adaptive. A completed call returns a SMCTuningSchedule; a cooperative stop before completion returns a distinct SMCTuningPartial, which SMCOptions(tuning=...) rejects. The reference pilot must finish before its Gaussian is fitted, and every grid pilot must finish before its kernel is published. Zero-draw initialization stops are supported.

progress is a Treebars parent node. Tuning creates a parent under it and a transient child for the reference pilot or each active grid pilot, with WarmupHMC's own progress underneath. Finished pilot subtrees are detached; the parent reports the current phase, boundary, window, evaluations and completed knots. The inner window counter can restart and is not a total-work percentage. Independent grid callbacks and checkpoint writes are serialized. Event order and the subset finished at a stop can vary with scheduling. After a stop request, other active pilots reach cooperative boundaries and may deliver callbacks; all workers join before the call returns or propagates an error. callback(snapshot, boundary) is observational: only literal true requests a stop. boundary is :init, :window, or :pilot after a completed pilot. The immutable scalar snapshot records phase (:reference/:grid), knot (zero for the reference), temperature, boundary, completed_knots, window, retained_draws and evaluations. The window is zero at :pilot; the evaluation count is for that pilot, with WarmupHMC's initialization exclusions above. A stop at the last completed pilot returns the ready schedule.

Requesting a Treebars interrupt on the supplied parent stops at initialization, an outer warm-up window or between pilots, just like the callback. These are cooperative boundaries, not hard wall-clock guarantees: initialization and a single window may exceed a host deadline. A pre-existing interrupt returns a partial before starting a pilot. Resume under a fresh, uninterrupted node.

With checkpoint_dir=dir, dir/tuning_latest.jls is atomically replaced before each callback and before starting a pilot. It contains the completed reference, completed kernels and work, outer RNG, current pilot seed and WarmupHMC's active checkpoint payload. A failure during a window can restart from the preceding boundary; work since that boundary is not saved. Only this latest outer record is retained. The active payload includes sampler draws and can grow with the active pilot; completed pilots retain no draws. Boundary history is capped by options.history_limit, independently of the finite grid's completed work. Independent-grid checkpoints retain each knot's seed and its active payload or completed kernel/work, plus the grid-start strategy. Their live payloads can therefore occupy memory for several pilots at once.

To resume, rebuild the original target (and previous, for an update), then call tune_smc with the original tuning keywords and either checkpoint_dir=dir, resume=true or resume=partial. The partial can also be serialized and restored in a fresh process. Both paths copy the saved continuation, skip completed pilots, and restore the active sampler through WarmupHMC's public resume API. The required rng argument is ignored on resume: the checkpoint supplies both RNG streams. No callback is repeated at the restored initialization/window boundary. Resuming a completed file returns its schedule without running another pilot or callback. options.nthreads may change on resume; it controls worker allocation, not the saved numerical continuation. Keep grid_start and other tuning settings unchanged. Switching strategy requires a fresh tuning run.

From 0.1.98, custom sampling expressions in coordinate identities use the same generated-namespace normalization as the built program. Rebuilt helper modules therefore need no aliases to the producing process's temporary module names. This does not migrate older checkpoints: keep their original runtime/package versions, and a file that already refers to a missing generated module cannot be recovered merely by rebuilding an equivalent module under a new name.

Resume checks Julia/package and checkpoint versions, target and previous-endpoint identities, binding, coordinate frame, tuning configuration and endpoint scores at saved positions. Caller IDs remain assertions about code/data semantics; finite score probes cannot prove arbitrary functions equivalent. Keep the code, data and non-default tuning settings unchanged. Progress and callback handles are supplied afresh, never serialized. Inputs and a supplied partial stay unchanged. Treat checkpoint arrays as read-only and do not advance/write one continuation concurrently. Deserialize only trusted checkpoints.

A fresh call refuses an existing tuning_latest.jls unless overwrite=true; overwrite cannot combine with resume and replaces only that file, preserving unrelated directory contents. resume=partial optionally writes its continuation to checkpoint_dir, allowing an explicitly selected saved boundary to be forked. Without a directory, an orderly stop still returns an in-memory checkpoint; unexpected exceptions or process loss then have no automatic disk recovery. If another CPU rounds the same scores differently, ordinary resume still refuses. Use rescore_smc_tuning_checkpoint to explicitly re-anchor the outer scores and active sampler payloads before resuming.

ReactiveKernelsPPL.update_smc Function
julia
update_smc(previous, target; options=previous.options, stages=typemax(Int))

Bridge a completed posterior cloud to a target for caller-supplied cumulative data in the same model and coordinate frame. The bridge density is (1-beta)*old_posterior + beta*new_posterior in log space, so priors and Jacobians occur once. Every mutation evaluates the required old/new histories from their beginning. This is full-history updating, not constant-cost streaming or a latent-state particle filter. No old terminal scan state is reused. If previous.options contains tuning for its old bridge, the default rejects: supply a freshly prepared update schedule, or explicit untuned SMCOptions.

with_cell_batch(visit, owner, u)

Evaluate cells at one copied packed point. owner is a CellQuery, CellFactors, or one of its value operators prepared with partitioned. The shared cache is refreshed once before visit(batch). WORKFLOW_WANTS

Preset want selections over generated programs, as a NamedTuple mapping preset name → the want argument. Prefer workflow_wants, which validates the preset name.

:pointwise returns a NamedTuple keyed by observation name. Elementwise observations retain their array shape; scalar and joint-vector draws return scalars, and broadcast joint draws return one density per slice. In-cell observations use their caller's data-column name and flat data shape. Conditioned declarations contribute here as observations. Summing every field gives :likelihood; prior-only models return an empty NamedTuple.

:observations returns, under the same keys, the arguments each observation's distribution receives: (location = …, scale = …) for responses of the Normal, Student t and LogNormal families, where entry i belongs to entry i of the response's :pointwise densities and a value shared by every observation stays a scalar.
